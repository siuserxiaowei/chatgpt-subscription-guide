# 维护规范

这页给以后修改本仓库的人。它不是给读者的操作教程。

读者先看首页充值教程，再看 [从选商品到查单的充值操作](chatgpt-recharge-guide.md)。六篇核对文是辅助，入口在 [辅助核对](../README.md#辅助核对)。

首页要直接回答怎么选、怎么买。购买步骤以当次公开商品页、价格目录和订单查询页为准。不要把仓库改回只剩帮助中心目录。不要抄第二份价格，也不要把商品页上的时效或保障口号写成新承诺。

## 商业关系必须写清楚

每篇教程开头保留一句维护说明，并链到 [谁在维护](../README.md#谁在维护)。

必须让读者知道三件事。

本仓库由 PayForGPT 维护，和商家有商业关联。

这不是 OpenAI 官方文档，也不是 GitHub 官方文档。

这不是独立第三方测评，也不保证收录、排名或购买转化。

不要把商家订单写成 OpenAI 官方结账。也不要把官方帮助页写成 PayForGPT 的承诺。

## 每篇教程要让人能做完

一篇教程只解决一个核对问题。至少包含这些标题。

这篇适合什么情况。

按这个顺序核对。

这时停下来。

下一步。

依据和核实日期。

尚未核实的内容。

步骤用有序列表，写成文字。可以配真实截图，但文字仍要写清打开哪里、点什么、下一步看到什么。图片要有能单独听懂的替代文字。不要伪造界面，不要把一组图片称作录屏，也不要留空的视频链接。标题按层级递进，不要从一级标题直接跳到三级标题。

段落保持短。链接文字脱离上下文也要能听懂，不要使用「点击这里」「详情」「here」。

可以参考 [会员付款这篇的核对顺序](tutorials/01-membership-and-api-balance.md#按这个顺序核对)。

## 官方名称和商品名称分开

OpenAI 帮助页里的计划名称，和 PayForGPT 的商品名称，必须分成两段写。

读者在官方页面上找不到一个叫做 5x 或 20x 的按钮时，教程应告诉他停下来，而不是把商品名解释成官方按钮。

商家页面自己对官方档位的对应说法，要标明出自哪一页、哪一次阅读。首页和退款页用词不一致时，写明两边都看到了什么，不要合成一个新名称。

价格、库存、用量倍数和消息上限不写入教程。读者去官方帮助页、自己的结账页，以及商家下单页看当次显示。

## 售后边界不要另写一份

退款、取消和质保只转述 [PayForGPT 退款与质保政策](https://payforgpt.com/refund) 里已经写明、并且记入事实核验记录的边界。

不要新增承诺，也不要把页面上的条件删掉后写成一句口号。个案以该笔订单的核验为准。

官方订阅的取消和退款，走 OpenAI 帮助页写明的平台。不要写成向 PayForGPT 申请就能取消 Apple 或 Google 的订阅。

## 凭据和安全

教程不得要求读者提交或上传这些内容。

密码、一次性验证码、API token、access token、session、cookie、查单密码、完整卡密。

可以告诉读者：订单号、付款时间、交易尾号、脱敏后的错误原文可以按求助篇准备。

不写绕过地区限制、风控、额度上限或账号限制的方法。官方帮助页明确说用量上限不能靠设置绕过时，保持这个意思。

## 链接

README 对 PayForGPT 的品牌说明只保留首页这一处。

教程里的主站链接只在该段任务需要时出现，例如退款边界、订单查询，或商品名和官方档位名的区别。不要每段都放购买链接，不要加跟踪参数。

内部链接使用相对路径。新教程文件先放进仓库，再把链接加进 README。不要链接还不存在的文章。

新增或更换外部链接时，先打开页面，再按 [事实核验记录](事实核验记录.md) 追加一条。直接请求若是 403、验证码或只有缓存标题，记录成「未从该次响应读到正文」。不要写成页面不存在，也不要写成正文已确认。

本仓库只服务 PayForGPT 这一处商家说明。不要加入其他商家、其他自营站点，或与本教程无关的产品介绍。

不批量翻译成其他语言。

## 提交前检查

在仓库根目录运行：

```bash
python3 scripts/check_internal_links.py --self-test
python3 scripts/check_internal_links.py --list-external
```

两条都通过，才说明内部链接和锚点可用。外部链接是否读到正文，仍看事实核验记录。

不要打开 GitHub Pages，不要绑定域名，不要给本仓库加付费功能。

合并到主分支之前，对外说明应写成「已提交，尚未合并」。不要写成教程已经发布。
